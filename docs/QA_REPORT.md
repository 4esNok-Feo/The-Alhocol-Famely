# Отчёт о тестировании

Версия: **1.0.0** · дата отчёта: 12 октября 2026 г.

Документ описывает, что именно проверено в этой сборке, чем проверено и **где проходят
границы проверки**. Всё, что не проверено, перечислено явно — это важнее, чем список
успешных тестов.

## 1. Итог одной строкой

Игра проходится от меню до экрана итогов, прогресс сохраняется, архив для платформы
собирается и запускается в распакованном виде. Публикация на платформе, живой SDK,
мобильные устройства и производительность на слабом железе — **не проверялись**.

## 2. Окружение

| Что | Значение |

| Node.js | v22.22.3 (`node --test`, ESM) |

## 3. Автоматические тесты

```bash
npm test        # node --test tests/*.test.js
```

Результат: **63 теста, 63 проходят, 0 падений**, время ~1,3 с.

| Файл | Тестов | Что проверяет |
| --- | --- | --- |
| `tests/run.test.js` | 24 | модель смены: штраф за продажу подростку, премия за отказ, окно сдачи, рост и спад стресса, пустые полки, границы очереди, детерминированность, состав итогов |
| `tests/career.test.js` | 14 | профиль и версия схемы, звёзды, XP, кошелёк, цели, открытие формы и улучшений, облачное хранилище, устойчивость к мусору в сохранении |
| `tests/bot.test.js` | 8 | играбельность: три звезды достижимы, аккуратный игрок зарабатывает больше невнимательного, касса не блокируется, бот не выходит за стены и успевает за ящиками, реакция на паспорт |
| `tests/platform.test.js` | 8 | `web/platform.js` на заглушках SDK: инициализация, `ready()`, пауза/возобновление, реклама, лимит частоты, отказ от облака, поведение без SDK |

Отдельно проверено, что тесты не «зеленеют» от пустоты: в `tests/bot.test.js` смена
проходится тем же ботом, что используется для замера баланса, а в `tests/web.test.js`
проверяется наличие файлов на диске, а не строки в исходниках.

## 4. Замер баланса

`npm run sim` прогоняет девять смен ботом и печатает таблицу. Более подробные серии
(20 семян на смену, три характера бота) дали:

| Бот | 1★ | 2★ | 3★ | Срывов смены |
| --- | --- | --- | --- | --- |
| `strong` | 180/180 (100 %) | 84 % | 54 % | 0 % |
| `normal` | 159/180 (88 %) | 68 % | 35 % | 0 % |
| `weak` | 138/180 (77 %) | 50 % | 22 % | 0 % |

Вывод: смена проходится даже при неуверенной игре, три звезды требуют почти безошибочной.
План по выручке выполняется ботом `normal` в 67–100 % прогонов в зависимости от смены.

## 5. Проверка собранного архива

Отдельный инструмент (`npm run verify`, `tools/verify_archive.js`) распаковывает
`dist/Katme_Yandex.zip` во временный каталог, поднимает заглушку браузера (без SDK
платформы — как в локальном предпросмотре) и запускает **игру из архива**.

Результат: **18 проверок, 18 проходит** — `index.html` в корне, модули и слой платформы
на месте, тестов и инструментов нет, внешних URL нет, `/sdk.js` подключён, игра стартует
без SDK и работает в локальном режиме, открывается меню, смена доигрывается ботом до
экрана итогов (3★, 8 069 ₽, 14 покупателей), итоги и звёзды в допустимых диапазонах,
прогресс записан в `localStorage` и читается назад, диагностика `window.__KATME__`
содержит `ready: true` и версию.

Это единственная проверка, которая ловит класс ошибок «в репозитории работает, а в
собранном архиве нет» — например, забытый файл или неверный путь.

## 6. Ручная проверка

- Прохождение всех девяти смен в браузере: зал, склад, касса, диалоги, пауза, перезапуск
  смены, экран итогов, меню, карьера, цели, оборудование.
- Проверка сохранения: прогресс, звёзды, XP и кошелёк переживают перезагрузку страницы;
  повреждённое сохранение не ломает игру (профиль пересоздаётся).
- Раскладка клавиатуры: управление одинаково работает на RU и EN, потому что клавиши
  читаются по физическому коду.
- Распаковка `dist/Katme_Yandex.zip` в чистый каталог и запуск через
  `python3 -m http.server`: смена проходится ботом, итоги и сохранение работают.
- 12 скриншотов (`npm run shots`) просмотрены вручную: HUD, диалоги, экран итогов.
- Обложка, иконки и тексты карточки проверены глазами.

## 7. Что было найдено и исправлено по ходу тестирования

| Проблема | Как проявлялась | Исправление |
| --- | --- | --- |
| Покупатель «зависал» на кассе после отказа | если весь чек состоял из «крепкого», покупатель оставался у прилавка навсегда, касса блокировалась, смена рушилась | `closeEmptyCheque()` в `src/core/run.js`: пустой чек закрывается сам, покупатель уходит |
| Бот бесконечно жал «отказ» | `pressRefuse()` возвращал `false`, а бот не выходил из ветки | проверка `restrictedPending` и выход из ветки в `src/ai/bot.js` |
| Касса простаивала, очередь «не приходила» | покупатели шли к кассе медленнее, чем обслуживались; игрок видел пустой зал у кассы | скорость покупателей приведена к скорости Катьме (`CUSTOMERS`), замер пропускной способности — в комментариях к `PHASES` |
| Смена была математически непроходимой | поток покупателей превышал скорость обслуживания даже без ящиков | интервалы прибытия в `PHASES` снижены до 12/9,8/8,2 с и обоснованы замером |
| Срыв смены был мгновенным | 100 % стресса рушили смену без шанса исправиться | добавлено «окно» 4 с (`STRESS.collapseGrace`) и предупреждение в HUD |
| Панель кассы перекрывала текст | строка «Отказать в продаже крепкого» рисовалась поверх последних позиций чека | высота панели считается с учётом строки отказа (`src/ui/hud.js`) |
| Крах при встраивании страницы | `window.__KATME__` создавался только в `index.html`, игра падала при другом хосте | `Game.patchDiagnostics()` создаёт объект сам (`src/game.js`) |
| Кадры рисовались слишком долго | размытие через `ctx.filter` на каждом кадре: съёмка 13 экранов занимала 600 с | размытие заменено на затемнение и вуаль, съёмка — 11 с |
| Колонка «% плана» в отчёте баланса врала | показывала долю прогонов, а не процент плана | переименована в «вып.» с пояснением, ширина колонок выровнена |
| Шрифты ехали в архив «мёртвым грузом» | 1,4 МБ TTF лежали в сборке, но `@font-face` не было: браузер рисовал системным шрифтом, и надписи на канвасе выглядели по-разному на разных ОС | добавлены `@font-face` в обе страницы и ожидание загрузки шрифтов перед первым кадром (`Game.waitForFonts`, таймаут 1,5 с) |
| В диагностике не было версии | `window.__KATME__` создавался страницей, а не игрой: при встраивании на чужую страницу версии и `ready` не было | `VERSION` объявлен в `src/core/config.js`, `patchDiagnostics()` пишет его всегда, версия сверяется тестом с `package.json` |

## 8. Границы проверки: что **не** тестировалось

1. **Публикация и модерация.** Сборка никогда не загружалась в консоль разработчика
   Яндекс Игр. Требования платформы к карточке нужно сверять в самой консоли.
2. **Живой SDK.** В песочнице нет `YaGames`, `sdk.js` не отдаётся. Инициализация SDK,
   `LoadingAPI.ready()`, реальные облачные сохранения, реальный показ рекламы,
   `game_api_pause` и `gameplayStart/Stop` проверены только на заглушках.
3. **Мобильные устройства.** Игра не проверялась на телефонах и планшетах: нет тач-управления,
   вёрстка рассчитана на горизонтальный экран, поведение виртуальной клавиатуры не изучено.
4. **Производительность.** Замеров FPS на слабых устройствах не делалось. Косвенно:
   кадр в сборе рисуется примитивами Canvas 2D, самая дорогая операция — затемнение
   поверх кадра на экранах меню.
5. **Кроссбраузерность.** Ручная проверка — в одном Chromium-совместимом браузере.
   Safari, Firefox и старые версии не проверялись.
6. **Доступность.** Нет режима для слабовидящих, нет переназначения клавиш, нет субтитров
   для звуковых подсказок. Шрифты и контраст не проверялись инструментами.
7. **Локализация.** Интерфейс только на русском; английские строки отсутствуют.
   Загрузка шрифтов проверена только логически (заглушка `document.fonts`), реальное
   поведение при медленной сети — нет.
8. **Godot-версия.** Проект в `godot/` повторяет модель смены, но проверялся только в
   редакторе: ни одного экспорта под платформу не собрано, звук и сохранение прогресса
   не перенесены, `Katme_Godot4.zip` в этом релизе не собирается.
9. **Долгие сессии.** Не проверялось поведение при многочасовой игре, при переполнении
   `localStorage` и при отключении звука на ходу.

## 9. Риски при публикации

| Риск | Вероятность | Что делать |
| --- | --- | --- |
| Замечания модерации из-за алкогольной тематики | средняя | заменить «крепкое» на энергетики в `src/core/config.js`, обновив тексты; механика проверки паспорта и отказа сохранится |
| Отклонение из-за возраста в карточке | низкая | ставить 18+, описание уже содержит прямое упоминание продажи крепкого |
| Реклама показывается слишком часто | низкая | в `web/platform.js` есть лимит 90 с и показ только после экрана итогов |
| Облачное сохранение конфликтует с локальным | средняя | при конфликте побеждает сохранение с большим числом звёзд; нужна проверка на живом SDK |
| Игрок не понимает, что делать | средняя | в игре есть подсказка-строка внизу, экран помощи по `Esc` и брифинг перед сменой; на реальных игроках не проверялось |

## 10. Как воспроизвести проверки

```bash
npm test                                  # 63 теста
npm run sim                               # таблица баланса по девяти сменам
npm run shots                             # 12 скриншотов в docs/screenshots/
npm run pack                              # dist/Katme_Yandex.zip + самопроверка
npm run verify                            # запуск игры из собранного архива
npm run check                             # тесты → сборка → проверка архива
python3 -m http.server 8000               # игра в браузере на http://localhost:8000/
```

`file://` не поддерживается: браузер не отдаёт ES-модули и шрифты по локальному протоколу,
поэтому нужен любой HTTP-сервер (в комплекте — `npm run serve`).
